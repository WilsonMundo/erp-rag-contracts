# Generic Analytics dashboard source V1 (PR-75D1)

`AnalyticsDashboardSourceV1` is an authorized, read-only public projection of a
**Generic AnalyticsArtifact**, distinct from legacy forecasting artifacts and
from AnalyticsExecution. Its normative schemas are
`contracts/runtime/analytics-dashboard-source-v1.schema.json` and
`contracts/runtime/analytics-dashboard-source-block-v1.schema.json`.
Package 2.11.0 adds these contracts without changing existing envelopes.

| Field | Authority |
| --- | --- |
| `source_kind` | Constant `analytics`. |
| `analytics_artifact_id` | Exact durable Generic AnalyticsArtifact referenced by the selected result's execution. |
| `display_title` | Durable artifact title, unchanged. |
| `blocks[].block_id` | Exact `presentation_definition.blocks[].block_id`. |
| `blocks[].kind` | Durable Generic Analytics block kind: `kpi`, `chart`, `table`, `summary`. |
| `blocks[].display_title` | Artifact title, as in Dashboard Editor Catalog; generic blocks have no independent title. |
| `blocks[].visual_type` | Durable `block.chart.type`, or null/omitted. |

Blocks are nonempty and their durable identities must be unique. The presentation
plan parser enforces uniqueness in ApiHub and the Python model enforces it on
validation; JSON Schema cannot compare the `block_id` property across array items.
Unknown properties, missing identities and execution-shaped/legacy-shaped sources
are rejected. An ID's spelling alone does not prove a generic artifact: ApiHub
must read and authorize the durable definition before producing this response.

ApiHub exposes
`GET /api/assistant/analytics/artifacts/by-result/{resultId}/dashboard-source`.
`resultId` is the existing persisted/public analytics result identity, not a
title, operation, result fingerprint or execution ID. It resolves through the
existing `analytics_results -> analytics_executions -> analytics_artifacts` join.
The result ID is only the lookup identity; the selectable source in the response
is always the exact **artifact** plus its **block** identities.

The authenticated tenant/user must own the artifact and the selected execution.
The existing editor catalog store additionally enforces active creator-owned
Generic Analytics definitions and ownership of every Query input. All input
QueryArtifacts pass the existing static authorization, AST fingerprint,
capability, requery and presentation-profile checks. Unavailable, foreign,
legacy, incomplete or unauthorized sources return no metadata (404); invalid
sessions return 401. No "latest execution" or human-metadata matching is allowed.

The same `AnalyticsDashboardSourceProjectionV1` produces presentation metadata
for this endpoint and Dashboard Editor Catalog. Binding options stay exclusively
in the dashboard-specific catalog; this response does not propose bindings,
execute analytics, expose SQL/rows, persist widgets or grant definition-write
permission. Add still uses the existing atomic definition PUT and its concurrency
token in a later AppWeb integration.

The canonical fixtures, Python schemas/resources and TypeScript exports are
generated by `tools/generate_artifacts.py`, with hashes in `contract-manifest.json`.
ApiHub embeds the schemas directly from this repository. One backend Fact verifies
the public DTO, schemas/fixtures, Python regeneration/model parity, TypeScript
exports, hashes and packaged resources together with lineage and authorization:
`PR75D1_generic_result_lineage_exposes_exact_authorized_dashboard_source`.
No extra contract suite or real E2E is run for this PR.
